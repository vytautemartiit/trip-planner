# 🎫 Trip Budget Planner

A full-stack application that helps plan trips within a budget — for single or multi-country journeys, with real-time currency conversion.

**[🔗 View demo](https://supreme-computing-machine-r777rj7qj9vq29w6-5173.app.github.dev/)**

## Why this project?

Most flight search tools (Skyscanner, etc.) search a single A→B route. This project solves a different problem: **"I have €500 and 8 days — where and how far can I travel, visiting multiple countries?"**

## Features

- 🔍 Search by budget and trip duration
- 🌍 Multi-country (2–3) combination generation and cost calculation
- 💱 Real-time currency conversion (Frankfurter API, ECB rates)
- 🎨 Custom UI design ("boarding pass" theme)
- ✅ Unit tests (pytest) covering the cost calculation logic
- 📱 Installable as a PWA (Progressive Web App)

## Tech Stack

**Backend**
- Python 3.12, FastAPI, Uvicorn
- Frankfurter API (currency rates)

**Frontend**
- React 19 (Vite)
- CSS (no UI libraries — hand-built design)

## Architecture
frontend (React) → backend (FastAPI) → Frankfurter API (currency)
↓
data.py (destination data)


The backend calculates trip cost using this formula:

total = flight_price + (hotel_per_night × nights) + (daily_cost × days)
For multi-country search, `itertools.combinations` generates every possible country combination, calculates total cost for each, and filters by budget.

## API Endpoints

| Endpoint | Description |
|---|---|
| `GET /search?budget=&days=` | Single-country search |
| `GET /search-multi?budget=&days=&countries=` | Multi-country combinations |

Full interactive docs available at `/docs` (Swagger UI, auto-generated by FastAPI).

## Deploying

- **Frontend** – GitHub Pages. Every push to `main` builds `frontend/` and publishes it (`.github/workflows/deploy.yml`).
  Set the repository variable `VITE_API_URL` (Settings → Secrets and variables → Actions → Variables) to the backend's address.
- **Backend** – any host that runs a container: `backend/Dockerfile` listens on `$PORT` (default 8000).
  Mount a volume at `/data` so the SQLite database (accounts, chats, tickets) survives restarts.
  Optional environment variables: `TICKETMASTER_API_KEY` (events), `ADMIN_TOKEN` (read reports at `GET /safety/reports`).
- **Tests** run on every push and pull request (`.github/workflows/ci.yml`).

## Known limitations / next steps

- Destination prices are currently static (`data.py`); from airports other than Vilnius they are distance-based estimates. Amadeus closed its free self-service API in July 2026, so live prices would need a paid provider.
- Days are split evenly between countries — a smarter (e.g. dynamic programming) split could reduce total cost.
- Possible additions: accommodation type selection, live flight prices.

## Trip info, verification and meeting locals

- **Trip info** per ticket: festivals and public holidays during your stay ([Nager.Date](https://date.nager.at)),
  the current travel advice for each country ([GOV.UK](https://www.gov.uk/foreign-travel-advice)) and the
  documents you need based on your nationality.
- **Live concerts and shows** come from the Ticketmaster Discovery API. They are optional: get a free key at
  https://developer.ticketmaster.com and start the backend with `TICKETMASTER_API_KEY=<your key>`.
- **Verified trips**: before chatting or meeting a local, travellers upload their airline PDF. The backend checks
  that it mentions every city and the departure date, keeps only a fingerprint of the file, and refuses the same
  file on a second account.
- **Meet a local**: people can offer to show visitors around a city in their home country; only travellers with a
  verified trip there can see them and ask to meet.

Backend dependencies are listed in `backend/requirements.txt` (`pip install -r requirements.txt`).

## Flying from another city

Pick your departure airport in **Flying from** above the search (32 airports, see `backend/origins.py`;
the frontend copy is `frontend/src/origins.js`). Fares in `data.py` are from Vilnius; from any other airport
the flight price is estimated from the distance and marked as an estimate. A trip never goes to the city you
fly from. `GET /origins` lists the airports; `/search`, `/search-multi` and `/destinations` take `?origin=CODE`
(default `VNO`).
